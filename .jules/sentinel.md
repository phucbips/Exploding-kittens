## 2024-05-24 - [Replace Insecure Math.random() with Web Crypto API]
**Vulnerability:** The application used `Math.random()` to generate Room IDs, randomize arrays for game shuffling, and randomly determine visual elements such as rotations. `Math.random()` is not cryptographically secure, which means its random values are predictable and can lead to potential game logic exploits or insecure IDs.
**Learning:** For a real-time multiplayer application where predictability directly impacts security or game integrity, weak PRNGs should not be used for logic like shuffling, distributing elements, or creating secrets/IDs. Next.js and modern browsers support `crypto.getRandomValues` and `crypto.randomUUID()` by default.
**Prevention:** In the future, enforce use of a secure random integer wrapper (e.g., `getSecureRandomInt`) or `crypto.randomUUID()` instead of `Math.random()`. Introduce linting rules that flag `Math.random()` if it is being used in sensitive paths or any game mechanics logic.
