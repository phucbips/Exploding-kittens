## 2024-11-20 - [Fix Exposed Database Rules and Insecure RNG]
**Vulnerability:** The Firebase Realtime Database rules (`database.rules.json`) were configured to allow global read and write access (`".read": true`, `".write": true`), exposing all game rooms to unauthorized access and modification. Additionally, the application relied heavily on the insecure `Math.random()` and `Date.now()` functions for generating room IDs, user IDs, shuffling the deck, and determining game logic (e.g., re-inserting the Exploding Kitten card). This made IDs and game state predictable.
**Learning:** Development environments often start with permissive rules to ease setup, but these must be locked down before production. Relying on `Math.random()` for any security-sensitive logic (like IDs or game state where predictability provides an unfair advantage) is unsafe.
**Prevention:** Always restrict Firebase rules to specific paths (`rooms/$roomId`) and explicitly deny global access by default. Use the Web Crypto API (`globalThis.crypto.getRandomValues()` and `globalThis.crypto.randomUUID()`) for generating unpredictable IDs and secure random numbers.
