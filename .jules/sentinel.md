## 2024-05-17 - Fix insecure Firebase Realtime Database rules
**Vulnerability:** The Firebase Realtime Database rules (`database.rules.json`) were configured with global `".read": true` and `".write": true` access. This allowed anyone on the internet to read, modify, or delete the entire database contents without any authentication or authorization checks.
**Learning:** This is a common default state during initial prototyping, but it exposes all game state (and potentially future sensitive data) to public manipulation. While this application does not use Firebase Authentication, authorization should still be strictly scoped to the data structures the application actually uses (in this case, just `rooms/$roomId`). Global access is a critical vulnerability.
**Prevention:** Always ensure Firebase rules are scoped down to the principle of least privilege before deploying. By default, rules should be `.read: false` and `.write: false` at the root, with specific paths enabled for the required operations. In this architecture, explicitly restricting access to the `rooms/$roomId` path prevents access to or creation of arbitrary data outside of the game logic boundaries.
