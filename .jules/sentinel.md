## 2024-05-18 - [Insecure PRNG for Game Logic and IDs]
**Vulnerability:** The application was using `Math.random()` to shuffle cards, select random variants, and generate security-sensitive identifiers (Room IDs, User IDs, Card IDs). `Math.random()` is not cryptographically secure and can be predicted. Additionally, `Date.now()` was used as a component of User IDs which makes them highly predictable.
**Learning:** For any mechanism involving game fairness (like shuffling a deck) or access control (like Room and User IDs that map to database state in Firebase without strict auth), generating randomness predictably breaks the security model of the application. The approach of using `Math.random().toString(36)` is fundamentally flawed for secure ID generation.
**Prevention:** Always use the Web Crypto API (`globalThis.crypto.getRandomValues()` or `globalThis.crypto.randomUUID()`) when generating unique identifiers or performing random operations that impact security or critical game mechanics. When replacing `Math.random()` for float generation (0 to 1), use `globalThis.crypto.getRandomValues(new Uint32Array(1))[0] / (0xFFFFFFFF + 1)` to maintain compatibility with `Math.floor` operations while ensuring cryptographic security.
