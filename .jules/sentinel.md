## 2025-02-28 - Insecure Firebase Realtime Database Rules Configuration
**Vulnerability:** The Firebase Realtime Database rules (`database.rules.json`) were configured to allow global read and write access (`".read": true, ".write": true`). This allowed any unauthenticated user to read or modify any data in the database, leading to potential data exposure and manipulation.
**Learning:** Default or overly permissive database rules are a common misconfiguration in Firebase projects, especially during early development phases. It's critical to establish strict rules from the beginning to prevent unauthorized access.
**Prevention:** Always follow the principle of least privilege when configuring database rules. Explicitly deny global read and write access at the root level (`".read": false, ".write": false`) and only grant access to specific paths required by the application's functionality (e.g., `"rooms": { "$roomId": { ".read": true, ".write": true } }`). Review and update these rules as the application's data model and authorization requirements evolve.
