## 2025-02-21 - Firebase Realtime Database Global Access Vulnerability
**Vulnerability:** The `database.rules.json` file was configured with global `.read: true` and `.write: true`. This is a critical security vulnerability that allows any unauthenticated user on the internet to read, write, or delete the entire database.
**Learning:** The application relies on unauthenticated custom IDs and `sessionStorage` instead of Firebase Authentication. This architectural choice means we cannot use standard `auth != null` checks in Firebase rules to secure data. Default open rules during development were inadvertently left in place.
**Prevention:** Always restrict Firebase Realtime Database rules by default. For applications not using Firebase Authentication, scope access as tightly as possible to specific paths (e.g., `rooms/$roomId`) and consider server-side validation or custom token generation if more granular security is required in the future. Never deploy global `.read: true` and `.write: true` in a production environment.
