## 2024-05-24 - [CRITICAL] Fixed Weak PRNG for Game Logic and IDs
**Vulnerability:** The codebase was relying heavily on `Math.random()` and `Date.now()` for security-sensitive logic, including room IDs, user IDs, deck shuffling, random variants, and bomb insertion points. `Math.random()` is not cryptographically secure, meaning its output is predictable. In a competitive or multiplayer card game like this, predictability could allow attackers to guess user IDs, manipulate room structures, or calculate deck states (e.g. tracking where bombs are inserted or what the shuffled order is), fundamentally breaking game fairness and security.
**Learning:** Found explicit memory prompt noting "Directive: Room IDs, user IDs, and game logic must use the Web Crypto API". The usage of insecure generators was pervasive across core utilities (`gameLogic.js`) and top-level pages. Predictable PRNGs are insufficient for game state critical vectors.
**Prevention:** Always use `globalThis.crypto.getRandomValues()` and `globalThis.crypto.randomUUID()` for PRNG logic where unpredictability is functionally or securely critical, such as deck randomization or ID assignments. Avoid raw `Math.random()` except in purely visual elements (e.g., frontend visual jitter).
