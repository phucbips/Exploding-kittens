## 2024-06-21 - [Secure Random Number Generation for IDs]
**Vulnerability:** The application was using `Math.random().toString(36)` and `Date.now()` to generate room IDs, user IDs, and player/card IDs. This provides low entropy and predictability, which can allow an attacker to guess active room IDs, spoof users, or predict game sequences.
**Learning:** `Math.random()` is not cryptographically secure, and using `.toString(36)` on typed array outputs doesn't behave as intended (returning static representations instead of actual encoded values). Furthermore, ID generation relying on predictable timestamps like `Date.now()` must be avoided.
**Prevention:** Use Web Crypto API methods (`globalThis.crypto.getRandomValues()` and `globalThis.crypto.randomUUID()`) to ensure cryptographically secure unpredictability. When generating string IDs using `getRandomValues()`, map the raw byte output to a specific character set rather than directly converting the array or its elements to base36.
