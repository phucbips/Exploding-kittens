## 2023-11-09 - Insecure Randomness via Math.random and Date.now
**Vulnerability:** Weak random number generation was used across the application for sensitive operations, including room ID generation (`Math.random()`), user/player ID generation (`Date.now()` and `Math.random()`), deck shuffling, and random insertion logic (like bomb placement).
**Learning:** `Math.random()` and `Date.now()` are predictable. When used for IDs (like room IDs), an attacker could theoretically predict active game sessions or user IDs. When used for shuffling, the deck order becomes predictable, compromising the integrity of a card game. Furthermore, direct character mapping from `Math.random().toString(36)` introduces severe biases.
**Prevention:** Always utilize the Web Crypto API (`globalThis.crypto.getRandomValues()` and `globalThis.crypto.randomUUID()`) for generating secure IDs, random variants, and shuffling. Implement rejection sampling (`getSecureRandomInt`) when creating bounded random integers to eliminate modulo bias.
