## 2025-02-14 - Insecure Randomness in Core Logic
**Vulnerability:** Core logic, including deck shuffling, unique ID generation (Room IDs, Player IDs, Card IDs), and bomb re-insertion, was relying on `Math.random()`. `Math.random()` uses a pseudo-random number generator (PRNG) that is not cryptographically secure, allowing potential predictability of the random values.
**Learning:** For game state mechanics, predictably generating game variables like deck orders or inserted card indices could allow a technically skilled user to predict deck outcomes or manipulate the client application into favoring them, breaking game fairness and logic. This codebase incorrectly used `Math.random()` to fulfill randomness for game arrays and ID generation.
**Prevention:** Instead of using `Math.random()`, use the Web Crypto API (`window.crypto.getRandomValues()` and `window.crypto.randomUUID()`) to generate cryptographically secure random integers for logic (like index selections or shuffle positions) and strings for IDs.
