## 2024-03-12 - [Predictable Random Number Generation]
**Vulnerability:** The application used `Math.random()` and `Math.random().toString(36)` extensively for critical game logic including shuffling the deck, choosing random card variants, inserting bombs into random indices, and generating supposedly unguessable Player and Room IDs.
**Learning:** `Math.random()` is not cryptographically secure. In a multiplayer card game, a predictable RNG could theoretically allow malicious players to calculate the random seed, predict the deck order, foresee bomb placements, or guess private room identifiers. This occurs commonly when developers prioritize standard math library convenience over security for non-financial operations.
**Prevention:** Always use the Web Crypto API (`crypto.getRandomValues()` or `crypto.randomUUID()`) for any random values related to security, identifiers, or hidden state (like game shuffles and ID generation). Established a new standard `utils/cryptoUtils.ts` containing `getSecureRandomInt()` and `generateSecureRoomId()` to encapsulate secure generation in the client.
